# Arquitectura — C4 Model

> Detalhe: `blueprint/02-ARQUITETURA-CONTRATOS.md` §4.

## C1 — Context

```
Utilizadores (Consumer, Pharmacist, B2B Buyer, Supplier, Driver, Admin)
        │
        ▼
  +------------------+        +-------------------------------+
  |    Brócolis       | ────► │ PostgreSQL · Redis · Storage   │
  |    System          | ────► │ (MinIO dev/test · Supabase sp)│
  +------------------+        +-------------------------------+
        │
        ▼  (payments)
  FinPay (a processadora) — tenants criam PaymentIntent e consomem webhooks HMAC
```

## C2 — Container

```
apps/web (Next.js 16)   ──oRPC──►  apps/api (NestJS 11 + oRPC + Prisma 7)
apps/mobile (Expo 57)   ──oRPC──►  apps/api
apps/api ──► Postgres 17 | Redis 8 | MinIO / Supabase Storage
apps/api ──► @brocolis/finpay ──► FinPay
apps/api ──► SMTP | WhatsApp API | Sentry
packages/contracts (Zod + oRPC) ── shared kernel ──► web, api, mobile, qa
```

## C3 — Component (dentro da API)

Módulos NestJS mapeiam 1:1 com bounded contexts. Cada módulo =
`controller + service + store(Prisma) + contract`. Middleware oRPC valida
sessão + role + `marketCode` por rota.
